# 三木点餐系统

自己写的点餐系统，基于 **Python + Qt（PySide6）+ SQLite**，面向 Windows 店内桌台点餐和收银。

当前版本：`0.4.0`，开发测试版。采用黄黑收银台布局，支持浅色、深色和跟随系统，可运行源码并打包 Windows exe。

## 已实现

- **桌号点餐**：主界面查看空闲 / 用餐中桌号，选择餐品下单、加减数量、移除餐品、取消订单。
- **桌台管理**：1–200 桌，支持自定义名称，例如“靠窗 01”“三木包厢”；有未结算订单的桌台不能停用。
- **餐品管理**：新增、编辑、分类、修改单价、上架、下架和直接删除；菜单删除后可立即撤销，旧账单继续保留。
- **分类下拉**：选择已有分类，或直接输入新分类名；同名分类复用，留空归为“未分类”。新增餐品可同名，每条记录独立保存。
- **深浅色主题**：右上角立即切换并永久保存，所有页面、分类列表和结算窗口使用统一主题；切换不会清空待编辑内容。
- **自动保存**：桌号、餐品、设置和未结算订单保存至 SQLite，退出和重启后可继续点餐。
- **结算确认**：默认显示餐品总价，可修改结算金额；输入折扣后立即显示最终实收。
- **店铺品牌**：上传自定义 Logo，左上角显示 Logo 与店名；Logo 保存进数据库，随备份一起保留。
- **小票排版**：Logo、店名、标题和页脚居中；餐品左对齐，数量、单价、金额右对齐。10 折不显示折扣，小票隐藏圆括号及括号内文字。
- **收入统计**：今日、按日、按月、按年和自选日期范围；查看实收收入、结算单数、平均每单、折扣优惠和汇总明细。
- **历史账单**：日历选择日期 / 日期范围，状态下拉筛选全部、已结算或已取消；查看小票、导出文本、补打，保留成交时的菜名、单价和小票内容。
- **Windows 驱动打印**：选择系统中已安装的打印机，支持中文小票和 58 / 80 毫米排版。
- **图形小票预览**：系统设置可预览样式，历史订单可预览实际账单；预览与打印共用排版，长菜名自动换行，长小票分页。
- **数据库备份**：使用 SQLite 在线备份接口，得到一致的数据库副本。

首次创建数据库时设置 8 个桌台和 3 道**示例餐品**。使用前请按实际情况修改桌数、菜单和价格。
从 0.1.0 升级时保留已有菜单，不会把现有餐品强制缩减为 3 道。

## 源码运行

环境：Windows 10 / 11（64 位），Python 3.11–3.14。
界面使用 Qt Widgets，依赖固定在 `requirements.txt`；不需要数据库服务器或浏览器。

**直接双击 `start.bat` 即可**。脚本首次启动会创建项目虚拟环境并安装界面依赖，以后使用该环境启动。
首次安装需要网络。也可以在 PowerShell 手动执行：

在 PowerShell 中运行：

```powershell
cd E:\TEMP\ordering-system
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

如果没有 `py` 命令，创建虚拟环境时使用 `python -m venv .venv`。

默认数据位置：

```text
%LOCALAPPDATA%\SanmuOrdering\sanmu.sqlite3
```

数据目录固定在当前 Windows 用户的本地应用数据文件夹，更新源码或移动 exe 不会改变它。
不同 Windows 用户默认使用各自的数据库。可在“系统设置”中查看实际路径。

开发测试使用独立数据目录，避免混入真实营业数据：

```powershell
.\.venv\Scripts\python.exe main.py --data-dir .\data
```

## 操作流程

1. 在“桌台管理”中设置桌数，选择桌台后可保存自定义名称；在“餐品管理”中维护菜单。
2. 打开“点餐收银”，点击桌台，再点击餐品卡片；也可先输入添加数量。添加餐品后自动开单和保存。
3. 账单中使用 `−`、`+` 调整份数，点击数量数字可直接输入；点击“删除”立即移除该项，不再二次确认。
4. 点“去结算”，核对默认带出的金额，可手动调整；输入折扣并查看下方最终实收。
5. 点“确认收款并结算”，在确认框核对实收金额；完成后桌号恢复空闲。
6. 在“收入统计”中选择今日、日期、月份、年份或日期范围，查看收入；双击明细跳到对应的已结算账单。
7. 在“历史订单”中使用日历和状态下拉框组合查询，也可查看、导出或补打小票。

### 自定义 Logo 与小票

1. 打开“系统设置”，填写“店铺名称”并保存；名称同步显示在软件左上角和新结算小票。
2. 点击“上传 Logo”，选择 PNG、JPG、BMP 或 WebP 图片，最大 10 MB、2500 万像素。上传立即保存；可点击“移除 Logo”恢复默认软件标识。
3. 图片会修正 EXIF 方向、按比例缩小至最长边 512 像素并存入 SQLite，删除原图片不影响软件使用。同一图片只保存一份。
4. 点击“预览小票样式”检查当前填写的店名、页脚、纸宽和 Logo。样式预览是示例账单，不创建订单或计入收入。
5. 打印 Logo 位于顶部中央并按比例显示，热敏小票采用白底黑白图；没有上传 Logo 时不预留图片空位。

餐品采用“餐品 / 数量 / 单价 / 金额”四列。抬头居中，数值右对齐，长菜名自动换行。
10 折不打印折扣行；有折扣时显示实际折扣及优惠金额；没有调价时不重复打印结算金额和零金额调整。
中英文圆括号及其内部文字仅在小票展示时隐藏，菜单及原始订单记录不受影响。

新结算账单保存成交时的店名、Logo、页脚和纸宽，更换或移除 Logo 后补打旧账单仍使用原图。
0.3.0 及更早的小票没有 Logo 快照，按保存的原始店名、页脚和纸宽重新排版，Logo 使用当前设置。
“导出文本”保留可复制的对齐文字；图片 Logo 显示在图形预览和打印小票中。

### 收入与历史筛选

- **收入按本机记录的结算时间归属日期**，使用折扣后的最终实收；例如前一天开单、今天结算，收入计入今天。
- 日期范围包含起止两天；按月统计自然月，按年统计自然年。年度明细按月汇总，其他方式按日汇总。
- 只统计已结算订单；未结算和已取消订单不计入。免单计为一笔已结算订单，收入为零。
- 平均每单 = 实收收入 ÷ 结算单数，四舍五入到分。折扣优惠 = 结算金额 − 最终实收，手动改价体现在餐品合计与结算金额的差额中。
- 无结算记录时汇总显示零，并显示空记录提示；明细只列出有结算的日期或月份。
- 历史状态下拉框支持“全部状态 / 已结算 / 已取消”，日期按结算或取消时间查询。
- 日期选择“单日 / 日期范围 / 不限日期”；选择后立即筛选，“查询”可刷新，“全部记录”清除日期和状态条件。
- 结算后自动刷新收入；再次进入统计页面会重新读取数据。主题切换保留当前筛选条件。

日历控件采用 [Qt QDateEdit](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QDateEdit.html)，支持中文日历及深浅色主题。

### 折扣规则

输入使用“折”：`10` 不打折、`9` 九折、`8.5` 八五折、`0` 免单。

```text
最终实收 = 修改后的结算金额 × 折扣 ÷ 10
```

例如餐品原价 128 元，结算金额改为 120 元，折扣输入 8.5，则最终实收为 **102 元**。
金额最多两位小数，折扣最多两位小数，最终实收四舍五入到分。
小票保留餐品合计和最终实收，有调价或折扣时显示相应明细；原始结算数据完整保存。

“确认收款”是人工确认已经完成收款，软件本身不连接微信 / 支付宝收款或银行卡支付。

## 美团打印机

**当前实现 Windows 打印机驱动接入；美团具体机型及连接方式尚未确认，尚未进行实体机出纸测试。**

如果该机型提供 Windows 驱动：

1. 按设备说明连接 USB / 网络并安装厂商驱动。
2. 在 Windows 中确认该设备能打印测试页。
3. 在驱动的“打印首选项”中设置实际纸宽、纸长和切纸方式。
4. 在应用“系统设置”中点击“刷新打印机列表”，选择设备，设置 58 / 80 毫米纸宽并保存。
5. 在结算窗口勾选打印，或通过历史订单补打。

应用纸宽控制小票布局；程序读取驱动的可打印范围和分辨率，将同一套图形排版居中输出。
实际纸张尺寸和切纸由驱动设置；小票较长时按驱动页面高度在完整内容块之间分页。
“已提交打印”表示 Windows 接收了打印任务，不表示打印机已经完成出纸。
遇到驱动报错时，结算记录仍然保存，可以检查 Windows 队列后补打，**不要重复结算**。

如果设备只支持美团云打印，不能直接使用当前的 Windows 驱动适配器。
后续需要具体型号、接入协议及对应平台授权，再实现云打印适配器；当前没有伪造或假定云接口。

打印实现参考：[Microsoft GDI 打印接口](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-startdocw)、
[StretchDIBits 位图输出](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-stretchdibits)；
后台图像绘制使用 [Qt QImage](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QImage.html)。

## 打包 Windows exe

当前阶段可使用源码测试。需要 exe 时，在 **Windows** 上双击 `build.bat`，或执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onefile --windowed --name SanmuOrdering main.py
```

输出文件为 `dist\SanmuOrdering.exe`。目标电脑无需另外安装 Python。
打包依赖单独固定在 `requirements-build.txt`，其中包含源码界面所需依赖。
版本更新时替换程序即可；默认数据库独立保存。发布前应在目标电脑完成打印及收银验收。

打包依据：[PyInstaller 官方文档](https://www.pyinstaller.org/en/stable/)。

## 从 0.3.0 升级

关闭旧窗口，更新源码后运行 `start.bat`。首次打开旧数据库时自动在同目录生成
`sanmu.before-v3-时间戳.sqlite3` 备份，然后添加 Logo 资源表及小票样式快照。
原有菜单、订单、收入和原始小票文字保留，无需安装额外依赖。
新版数据库请使用 0.4.0 或更新版本打开。

## 0.3.0 的收入统计升级说明

关闭旧窗口，更新源码后运行 `start.bat`。0.3.0 使用原有数据库结构，直接从已保存的账单计算收入，
无需重新录入菜单、订单或安装额外依赖。

## 从 0.1.0 升级

关闭旧版窗口，更新源码后运行 `start.bat`。数据目录保持不变。
首次打开旧数据库时，程序会先在同目录保存 `sanmu.before-v2-时间戳.sqlite3` 备份，
再升级餐品表以支持删除和同名餐品；旧菜单、订单和小票全部保留。
这一步之后会继续升级到当前数据库版本，不要使用旧版程序继续操作升级后的数据库。

## 备份与恢复

在“系统设置”点击“备份数据库”，选择其他目录保存 `.sqlite3` 文件。
正在运行时请使用此备份功能，避免遗漏 SQLite 的 WAL 文件。

恢复前关闭所有本程序窗口，保留现有数据目录副本；推荐将备份复制到一个新文件夹，
命名为 `sanmu.sqlite3`，然后以 `--data-dir 新文件夹` 启动验证。
不要在应用运行中直接覆盖数据库。日志保存在同一数据目录的 `sanmu.log` 中。

```text

sanmu/
  ui.py                 Qt 页面、结算确认、打印任务管理
  report_ui.py          收入统计页面、日期筛选及账单跳转
  reports.py            日 / 月 / 年统计范围与日期校验

  widgets.py            卡片、分类选择器等可复用界面组件
  storage.py            SQLite 表结构、事务、订单、设置及备份
  money.py              金额和折扣校验计算
  receipts.py           小票文字、四列表格、成交样式与旧版兼容
  receipt_render.py     共用图形排版、居中定位与分页
  receipt_widgets.py    Logo 标识和白纸小票预览
  branding.py           图片导入、格式和尺寸验证
  printing.py           Windows GDI 位图打印
  __main__.py           数据路径、日志和启动

build.bat               Windows exe 打包
```

公开仓库只存放源码、测试和文档；数据库、日志、虚拟环境与打包输出均已配置 Git 忽略。
